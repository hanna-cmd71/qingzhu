# 青竹剑阵 2.x 迭代线

状态：**进行中**。2.0 为基线，之后每版 +0.1，目标是达到可发布的成熟度。本页记录每一版的定位、改动范围与验收证据；正文只写已落地的内容，计划不写成已实现。

## 迭代主线（作者 2026-10-12 指定）

按此顺序推进，每版都重建两份离线 HTML 并跑全量回归：

1. **手感与战斗打磨**——命中反馈、打击感、镜头、音效层次、难度曲线。
2. **新手引导与可读性**——开场引导、机制教学、界面提示与信息层级。
3. **表现与美术品质**——特效、UI 视觉、动画流畅度。
4. 之后对上述三条线做第二轮深化与整体收口，直至达标。

版本号规则：显示版本取 `game/gameplay/version.js` 的 `GAME_VERSION`，包版本同步 `X.Y.0`，发布标签 `vX.Y`。存档格式 1、存档键、records schema 与各系统子版本号不随显示版本变动。更新日志每版一行、逐版追加，首行即当前版本。

## 2.0 正式发布（基线）

把 WP0—WP10 的 v2.0 需求整体落地并发布：时装系统（4 套 + 默认）、御剑法门（4 把）、流派技能（六起手各 1 个主动技能）、平衡矩阵（30 格 × 6 流派 = 180 局固定策略输出）。显示版本从 1.0 抬到 2.0，1.0 存档可继续游玩，不清档、不补造记录。

验收：全量单元测试、五个浏览器批次 ×2 资源档、技能界面核对 35/35、平衡证据 `docs/qa/balance-v2.json`。详见 [v2.0 需求文档](v2.0-requirements.md)。

## 2.1 手感与战斗打磨

定位：把"能打"变成"打得爽"。全部改动都在表现层——不消费战斗随机数、不进快照、不改任何规则分支。

| 改动 | 内容 |
|---|---|
| 命中顿帧 | 击杀 45 ms、受击 50 ms、符爆 50 ms、神雷 80 ms、剑意合体 100 ms、首领变招 140 ms、首领阵亡 200 ms。一次只冻结一次，两次之间留 120 ms 间隔，轻击被限流挡住、重击可穿过，总时长上限 300 ms。可在设置关闭（默认开启） |
| 受击白闪 | 敌人被命中时叠加预制白色剪影，替代原来"整体降透明度"的提示；白闪按 0.1 秒线性衰减 |
| 震动按时间衰减 | 原来每帧乘 0.85，在 144 Hz 屏幕上几帧就归零；改为按真实时间衰减，各刷新率下手感一致 |
| 伤害数字分级 | 数字随伤害量级放大（最高 +30%，暴击 +45%），暴击再高一档并保留上限，避免后期数字撑破版面 |
| 音效层次 | 击杀补一层低频并提高音量（0.025 → 0.05），暴击单独提权到 0.07 |

实现落在 `game/gameplay/feel.js`（唯一数据源：时长、限流阈值、衰减与放大曲线），引擎按 impact 名称发 `hitstop` 事件，渲染循环消费，设置页文案由同一张表生成。

## 2.3 表现与美术品质

定位：把「看得见」变成「打得亮」。全部改动都在表现层——不消费战斗随机数、不进快照、不改任何规则分支；每个特效的数据形状与几何位置都与 2.2 逐字节一致。

改前的缺口：2.2 及以前，所有特效都是**单层细描边 + 线性淡出**——没有加色混合、没有分层辉光、没有火花；飞剑尾迹也只是一条细线。暗底上打出来的东西「有形状、没亮度」。

| 改动 | 内容 |
|---|---|
| 辉光分层 | 符爆、剑痕、剑意合体、神雷、闪电与剑意连线各叠一层加色混合（`globalCompositeOperation='lighter'`）的宽描边，宽度 6–16 px、不透明度 0.22–0.30，压在 2.2 原有那一笔下面；原有那一笔的宽度、颜色与几何完全不变 |
| 冲击火花 | 剑痕 6 粒、剑意合体 10 粒、符爆 8 粒，在特效存续期间向外飞散；落点由序号与进度算出，不取随机数 |
| 飞剑尾迹 | 尾迹下面垫一层更宽的加色辉光；阵图编成时沿用阵位角色色，与原尾迹同色系 |
| 御剑笔画 | 笔迹与笔头各加一层加色辉光，正在飞的那一笔在战场底色上先被看到 |
| 剑意合体 | 横扫弧线加一层 26 px 的加色外发光，合体才有「劈开」的亮度 |
| 冲刺残影 | 残影改用加色混合叠加，像御剑留下的灵光而不是半透明贴图 |
| 布阵与首领消散 | 布阵瞬间铺一层加色柔光；首领消散的扩散环加一层 16 px 外发光 |
| 画质档 | 设置页「飞剑尾迹」档位扩为「**画面特效**」，一次控制上面全部光晕与尾迹；选「精简」时整层不画，像素与 2.2 一致 |

## 2.4 打击反馈与界面动效

定位：主线第 4 项「对上述三条线做第二轮深化」的第一轮，承接 2.1 的手感与 2.3 的表现，把「打中了」变成「打得有反馈」。全部改动都在表现层——不消费战斗随机数、不进快照、不改任何规则分支。

改前的缺口：血条只有一条 0.1 秒的宽度过渡，掉多少血看不出来；受伤只有震动与飘字，屏幕本身没有反应；生命见底只是血条变红加一个「!」；伤害数字是固定字号的线性上浮；场景对话框与提示条都是硬切。

| 改动 | 内容 |
|---|---|
| 血条伤害滞后 | 真实血条先掉到当前值，后面留一条浅色残影慢慢追上来，约 1.8 秒追平，所以「这一下掉了多少」看得见。回血时残影直接跟上，不会读成血更少。玩家、首领、精英、符印、护持阵盘与画布上的韩立血条都覆盖 |
| 受击屏幕红晕 | 受伤时屏幕四边泛红，强度按「这一下掉了多少血」累积（一次掉三成血接近满强度），随后按 1.7 / 秒衰减。上限 0.5，保证战场不被盖住 |
| 低血量呼吸脉冲 | 生命低于 30% 后，边缘红晕改为按 0.62 Hz 的呼吸节奏明暗脉动，越低越深。用 sin 计算，同一时刻重画得到同一画面，也不取随机数 |
| 伤害数字弹出 | 出现瞬间放大到 1.5 倍再收回，上浮 26 px 且先快后慢；原来是一条线性上浮的固定字号 |
| 场景对话框 | 淡入时叠加 0.985 → 1 的中心缩放。**中心点在缩放中不变**，所以按坐标点击的验收脚本仍落在同一个位置；不做位移 |
| 提示条 | 只淡入透明度，不动 transform——窄屏有 `transform:none` 的覆盖规则，用关键帧写死 `translateX(-50%)` 会把窄屏提示条推偏 |
| 开关 | 设置页「受击震动」扩为「**受击反馈**」，一次控制镜头震动、屏幕红晕与低血量脉冲。沿用既有 `settings.shake`，不新增存档字段 |

实现落在 `game/gameplay/impact.js`（唯一数据源：滞后速度、红晕累积与衰减、脉冲曲线、数字弹出与上浮曲线、设置页说明），`meters.js` 的 `drawHealthBar` 增加可选的滞后比例参数（不传时与 2.3 逐像素相同），`art.js` 的渲染器持有血条残影与红晕两个私有状态（不进快照），`Game.jsx` 的血条加一层残影元素、设置页说明由 `impactSummary()` 生成。

## 2.5 表现总控与整体收口

定位：主线最后一项「对上述三条线做第二轮深化与整体收口」的收口版。2.1—2.4 各开了一条表现线、各留了自己的开关，2.5 不再开新线，而是把这些开关收在同一个判据下，并把设置页整理成能看懂的样子。全部改动仍在表现层——不消费战斗随机数、不进快照、不改任何规则分支。

改前的缺口：2.1—2.4 一共给玩家留下六个表现开关（受击反馈、命中顿帧、神雷闪光、普通伤害数字、首次机制提示、画面特效），但没有任何一处回答「我现在这一套组合实际会看到什么」；系统级的 `prefers-reduced-motion` 只在 CSS 里零散处理，画布完全不理它——于是在系统里选了「减少动态效果」，界面停了、画面还在震；设置页把「画面」和「辅助」两类开关混在同一个列表里，看不出归属。

| 改动 | 内容 |
|---|---|
| 动效总闸 | 新增「动效」三档：**跟随系统**（默认，按操作系统的「减少动态效果」自动切换）、**完整**、**减少**。它压在上面六个开关之上，只决定「会动或会闪的那一部分」播不播，不改变任何一项开关本身的含义 |
| 统一判据 | `MOTION_POLICY` 表列出减少动效时停掉的 8 项：镜头震动、命中顿帧、受击白闪与神雷闪光、伤害数字弹出与上浮、低血量呼吸脉动、火花与冲刺残影、血条掉血残影、场景与提示淡入 |
| 静态提示保留 | 减少动效只去掉「动」的那一半：掉血的红晕照画（只是不再按呼吸脉动）、伤害数字照显示（只是原地不动）、加色辉光、来袭预警与提示文字全不变 |
| CSS 与画布同源 | `Game.jsx` 把 `motionAttribute()` 写到 `<html data-motion>`，CSS 读同一条规则；系统偏好变化时重新计算，所以不会再出现「界面停了画面还在动」 |
| 设置页分组 | 「声音与画面」里加「画面表现」与「辅助与提示」两个小标题，八个开关各归其位 |
| 表现总览 | 由 `presentationLedger()` 生成：当前动效档、画面特效档、六个开关状态、特效类数与低血量阈值一次列全，并重申「只影响画面」 |

实现落在 `game/gameplay/presentation.js`（唯一数据源：三档与坏值回落、`reducedMotion` 纯函数、取舍表、总账与设置页文案），`art.js` 每一帧算一次 `allow(kind)` 并据此决定震动／白闪／神雷闪光／数字弹出／低血量脉冲／火花／血条残影（`drawObjective` 因此多收一个 settings 形参），`Game.jsx` 用同一判据门控顿帧并同步 `<html data-motion>`，`game.css` 加一条 `html[data-motion=reduced] *{transition:none!important;animation:none!important}`。
